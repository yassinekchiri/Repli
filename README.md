# NetApp Cascade Migration

*Version française : [README.fr.md](README.fr.md)*

NetApp ONTAP migration orchestration tool built around a **Y topology**: a
source volume is replicated through a pivot cluster to **two simultaneous
destinations** (PROD + DR), then split into clone volumes (1 volume = 1 qtree).

```
    [ SOURCE ]  source cluster
         |
         |  SnapMirror (relationship 1)
         v
    [ PIVOT  ]  transit cluster
        /  \
       /    \      relationships 2 and 3 (simultaneous fan-out)
      v      v
  [ PROD  ]    [ DR ]
```

All calls to the clusters go through the **ONTAP REST API** (basic
authentication) by default. An SSH transport is kept as a fallback
(`--transport ssh`). The same **engine** is used by both interfaces: the
**CLI** and a **REST API** (FastAPI).

Minimum ONTAP version: 9.9.1 — validated against 9.16.1.

## 1. Architecture

```
netapp_migration/
├── config.py               # REST credentials + job directory
├── models.py               # shared dataclasses (params, errors, ONTAP objects)
├── transport/
│   ├── base.py             # OntapClient: the abstract contract
│   ├── rest.py             # ONTAP REST API implementation (default)
│   ├── ssh.py              # ONTAP CLI over SSH implementation (fallback)
│   └── dryrun.py           # --dry-run simulation (no cluster contacted)
├── core/
│   ├── engine.py           # MigrationEngine: the 8 business actions
│   └── jobs.py             # JobStore: JSON job files + checkpoints
└── interfaces/
    ├── cli.py              # command-line interface
    └── api/
        ├── app.py          # FastAPI application
        └── schemas.py      # Pydantic request/response models

netapp_cascade_migration.py # CLI entry point (historical compatibility)
requirements.txt
```

Job files (`netapp_migration_<ID>.json`) are **compatible** with the ones
generated by the old single-file version of the script.

## 2. Installation

### 2.1 Prerequisites

* Python **3.9+** (validated on 3.11)
* HTTPS (443) network access to the ONTAP cluster management LIFs
* An ONTAP account with REST API privileges (`admin` role or a dedicated
  role granting access to the `storage`, `snapmirror` and `protocols`
  endpoints)

### 2.2 Steps

```bash
# 1. Get the code
git clone <repo-url> && cd Repli

# 2. Create a virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 3. Install the dependencies
pip install -r requirements.txt

# (optional) SSH transport with the paramiko backend:
# pip install paramiko
```

### 2.3 REST credentials configuration

Create a `creds.json` file (protect it: `chmod 600 creds.json`):

```json
{
  "defaults": {
    "username": "svc_migration",
    "password": "********",
    "verify_ssl": false,
    "port": 443
  },
  "clusters": {
    "CMOPARPA4SFS100": { "verify_ssl": true },
    "CMOPARDC5SFS100": { "username": "other_account", "password": "********" }
  }
}
```

* `defaults` applies to every cluster; each `clusters` entry overrides the
  values for one specific cluster.
* `verify_ssl: false` is required when the LIF certificates are
  self-signed (a warning is logged).

The file is provided via `--config creds.json` (CLI) or the
`NETAPP_MIGRATION_CONFIG` environment variable (CLI and API).

Alternative without a file — environment variables:

```bash
export NETAPP_API_USER="svc_migration"
export NETAPP_API_PASSWORD="********"
```

### 2.4 Job directory

By default job files are written to the current directory.
For a fixed location (recommended for the API):

```bash
export NETAPP_MIGRATION_JOB_DIR=/var/lib/netapp-migration/jobs
mkdir -p "$NETAPP_MIGRATION_JOB_DIR"
```

## 3. Command-line usage

```bash
export NETAPP_MIGRATION_CONFIG=/path/to/creds.json
```

### 3.1 create — initialise the cascade

```bash
python3 netapp_cascade_migration.py --action create \
    --source-cluster CMOPARTIGMUT100 \
    --pivot-cluster  CMOPARTIGBKP110 \
    --dest-cluster   CMOPARPA4SFS100 \
    --dr-cluster     CMOPARDC5SFS100 \
    --volume vol_prod_01 \
    --pivot-aggr aggr1_pivot --dest-aggr aggr1_dest --dr-aggr aggr1_dr
```

Two-phase mode (launch the pivot, come back later):

```bash
python3 netapp_cascade_migration.py --action create ... --create-mode pivot-only
python3 netapp_cascade_migration.py --action check-status --job-id <ID>
python3 netapp_cascade_migration.py --action resume       --job-id <ID>
```

### 3.2 retry — resume a failed create

```bash
python3 netapp_cascade_migration.py --action retry --job-id <ID>
```

Resumes at the last checkpoint (`space_checked`, `volumes_created`, ...);
already-completed creations are skipped (idempotent).

### 3.3 test — full test environment (no disk space consumed)

```bash
python3 netapp_cascade_migration.py --action test --job-id <ID> \
    --qtrees all --test-validity-days 7
```

Builds the **complete** target environment **except the split / volume
move**: FlexClones `v_<qtree>_<uid>` on the future PROD **and** the future
DR, with the **SnapMirror relationships between the clones** (resync waited
to idle). The clones stay attached to their parent DP volume: zero disk
space consumed.

The environment is **time-limited** (`--test-validity-days`, default
7 days; the expiry date is stored in the job file). Before that date:

* the client validates access and permissions;
* `--action clone` **promotes** this environment to the definitive one
  (only the volume moves are launched — nothing is rebuilt);
* otherwise, past the date, the clones must be **deleted** (the exact
  commands are printed at the end of the action).

One `test` invocation per job: running `test` again while an environment
exists is refused (promote it or delete it first).

### 3.4 acl — force AD groups on a path (NetApp-side DACL)

Action **fully decoupled** from `test` and `clone`: it acts on **one path**
provided by the client, invocable on any path of his destination volumes.

```bash
python3 netapp_cascade_migration.py --action acl --job-id <ID> \
    --acl-path /v_q_fin_8072b8/projects \
    --ad-groups 'CORP\grp_rw,CORP\grp_ro' --acl-rights modify
```

`--acl-path` is mandatory (absolute path on the destination vserver).
The forcing is propagated through the whole tree (folder, sub-folders,
files) on the PROD side; DR receives the ACLs through the clone SnapMirror
replication.

### 3.5 clone — definitive clones + detachment

```bash
python3 netapp_cascade_migration.py --action clone --job-id <ID> --qtrees q_fin,q_hr
```

Three modes:

* **Promotion** (default when a `test` environment exists): the clone
  mirrors are checked idle, then `volume move` (detachment from the
  parents). Nothing is rebuilt; the requested qtrees must match the ones
  of the test run.
* **`--fresh`** — start from a clean base **even if a test environment
  exists**: the test environment is ignored and the full flow runs (new
  snapshot, new clones with a new UID). The old test clones stay in
  place; the commands to delete them are printed at the end of the run.

  ```bash
  python3 netapp_cascade_migration.py --action clone --job-id <ID> \
      --qtrees q_fin,q_hr --fresh
  ```
* **Full flow** — no test environment: dedicated snapshot → cascade
  propagation → FlexClones on PROD and DR → SnapMirror between the clones
  + resync → automatic best-aggregate selection → `volume move` →
  immediate exit.

### 3.6 cleanup — cut source access

```bash
python3 netapp_cascade_migration.py --action cleanup \
    --source-cluster ... --pivot-cluster ... --dest-cluster ... \
    --volume vol_prod_01 --qtree q_fin
```

### 3.7 Cross-cutting options

| Option | Purpose |
|---|---|
| `--transport rest\|ssh` | ONTAP transport (default: `rest`) |
| `--config PATH` | REST credentials file |
| `--api-user USER` | REST login override (password via env/config) |
| `--insecure` | skip TLS verification (self-signed certificates) |
| `--job-dir PATH` | job files directory |
| `--dry-run` | full simulation, no cluster contacted |
| `--yes` | (resume) skip the interactive confirmation |
| `--timeout` / `--poll-interval` | SnapMirror polling (s) |
| `--log-file PATH` | log file (default: `migration_<action>_<date>.log`) |

The console shows only the progress; the **log file** contains the full
DEBUG trace (every REST call with its payloads, or every SSH command with
stdout/stderr).

## 4. Running the REST API

### 4.1 Startup

```bash
source .venv/bin/activate
export NETAPP_MIGRATION_CONFIG=/path/to/creds.json
export NETAPP_MIGRATION_JOB_DIR=/var/lib/netapp-migration/jobs

uvicorn netapp_migration.interfaces.api.app:app --host 0.0.0.0 --port 8000
```

Interactive documentation (Swagger UI): `http://<server>:8000/docs`

> **Important**: run a **single worker** (no `--workers N`) — the registry
> of running actions lives in process memory.

### 4.2 Endpoints

| Method | Endpoint | Action | Answer |
|---|---|---|---|
| `POST` | `/api/v1/migrations` | create | `202` + job_id (background) |
| `GET`  | `/api/v1/migrations` | list all jobs | `200` |
| `GET`  | `/api/v1/migrations/{id}` | job record + last action (logs) | `200` |
| `GET`  | `/api/v1/migrations/{id}/status` | live replication state (queries ONTAP) | `200` |
| `POST` | `/api/v1/migrations/{id}/resume` | PROD + DR fan-out | `200` / `409` |
| `POST` | `/api/v1/migrations/{id}/retry` | resume after a failure | `202` (background) |
| `POST` | `/api/v1/migrations/{id}/test` | full test env (clones + mirror, time-limited) | `202` (background) |
| `POST` | `/api/v1/migrations/{id}/clone` | definitive clones (test promotion, or `fresh` / full flow) | `202` (background) |
| `POST` | `/api/v1/migrations/{id}/acl` | force AD-group DACLs on a path | `200` |
| `POST` | `/api/v1/migrations/{id}/cleanup` | cut source access | `200` |
| `GET`  | `/api/v1/health` | service availability | `200` |

Long actions (`create`, `retry`, `test`, `clone`) answer `202` immediately
and run in the background; follow their progress with
`GET /api/v1/migrations/{id}` (state + last log lines). One action at a
time per job (`409` otherwise).

### 4.3 curl examples

```bash
BASE=http://localhost:8000/api/v1

# Create the cascade
curl -s -X POST $BASE/migrations -H 'Content-Type: application/json' -d '{
  "source_cluster": "CMOPARTIGMUT100",
  "pivot_cluster":  "CMOPARTIGBKP110",
  "dest_cluster":   "CMOPARPA4SFS100",
  "dr_cluster":     "CMOPARDC5SFS100",
  "volume": "vol_prod_01",
  "create_mode": "pivot-only"
}'
# -> {"job_id": "20260704_105603_2e70af", ...}

JOB=20260704_105603_2e70af

# Follow the progress (job record + last action logs)
curl -s "$BASE/migrations/$JOB?logs=30"

# Live replication state (queries the clusters)
curl -s $BASE/migrations/$JOB/status

# PROD + DR fan-out: a first call without confirm answers 409 when the
# pivot is ready; confirm explicitly:
curl -s -X POST $BASE/migrations/$JOB/resume \
     -H 'Content-Type: application/json' -d '{"confirm": true}'

# Full test environment (clones + PROD->DR mirror, limited to 7 days)
curl -s -X POST $BASE/migrations/$JOB/test \
     -H 'Content-Type: application/json' \
     -d '{"qtrees": ["q_fin", "q_hr"], "validity_days": 7}'

# Force AD groups on ONE specific path (decoupled from test/clone)
curl -s -X POST $BASE/migrations/$JOB/acl \
     -H 'Content-Type: application/json' \
     -d '{"ad_groups": ["CORP\\grp_rw"], "acl_path": "/v_q_fin_8072b8/projects",
          "acl_rights": "modify"}'

# Definitive clones: promotes the test environment when one exists
# (volume moves only), otherwise full flow
curl -s -X POST $BASE/migrations/$JOB/clone \
     -H 'Content-Type: application/json' -d '{"qtrees": "all"}'

# Definitive clones on a clean base, ignoring the test environment
# (the old test clones remain and must be deleted manually)
curl -s -X POST $BASE/migrations/$JOB/clone \
     -H 'Content-Type: application/json' -d '{"qtrees": "all", "fresh": true}'

# Cut source access for a migrated qtree
curl -s -X POST $BASE/migrations/$JOB/cleanup \
     -H 'Content-Type: application/json' -d '{"qtree": "q_fin"}'
```

## 5. Migration life cycle

```
create (pivot-only) ──> check-status ──> resume ──> check-status ... completed
        │                                                    │
        └── retry (on failure, resumes at the last checkpoint)
                                                             │
                                                             v
              test (full env: clones + mirror, no move, limited to N days)
                                                             │
                     client validation (access, permissions) │
                                                             v
              ┌─ before expiry : clone = PROMOTION (volume moves only)
              ├─ at any time   : clone --fresh = full flow on a clean base
              │                  (old test clones left to delete)
              └─ after expiry  : delete the test clones,
                                 then clone = full flow
                                                             │
                                                             v
                                                          cleanup

acl (independent): at any time, on any destination path
```

Job-file checkpoints (`--action retry` resumes at the last one reached):

```
started → space_checked → volumes_created → relationships_created
        → pivot_initialized → dest_initialized → completed
```

After `test`, the job file contains `clone_uid`, `clone_volumes`,
`test_env`, `test_created_at` and `test_expires_at`; promotion through
`clone` flips `test_env` to `false` and records `clone_promoted_at`.
A `clone --fresh` replaces `clone_uid`/`clone_volumes` with the new run's
values — the old test clones remain on the clusters and are listed at the
end of the run for manual deletion.

## 6. Troubleshooting

* **401/403 from the ONTAP API**: check the account in `creds.json` and
  that its role allows REST access (`security login show`).
* **TLS error**: self-signed certificates → `"verify_ssl": false` in the
  credentials file, or `--insecure` on the CLI.
* **`job file not found`**: run the command from the same
  `NETAPP_MIGRATION_JOB_DIR` (or the same current directory) as the
  original run.
* **`409 action already running`** (API): another action is already
  running for this job; wait for it to finish (`GET /migrations/{id}`).
* **Full trace**: the `migration_<action>_<date>.log` file contains every
  REST/SSH call at DEBUG level.
